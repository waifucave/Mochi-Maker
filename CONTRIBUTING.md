# Contributing

Thank you for helping with Mochi Maker. This page covers building and testing, what a change
needs, and the sign-off every contribution carries.

## Build and test

Requires Node 20 or later (CI uses Node 22).

```sh
npm ci
npm run build          # the TypeScript packages
npm run build:editor   # the editor's web build (Vite)
npm run check          # typecheck (sources and tests), all tests, and formatting
```

- `npm test` runs the Node tests, then the editor's browser tests one file at a time. The browser
  tests, the pixel checks and the rendering tests need Chromium through Playwright
  (`playwright-core`); without it they are skipped, and CI runs them.
- `npm run format` formats the sources with Prettier; `npm run format:check` is part of
  `npm run check`.
- The desktop app: `npm run start -w @mochi-maker/desktop` after `npm run build:editor`, and
  `npm run package:linux -w @mochi-maker/desktop` for an unsigned Linux build
  ([`docs/desktop.md`](docs/desktop.md)).
- Tests run with the feature flags `glue` and `blendShapes` on
  ([`docs/core.md`](docs/core.md#feature-flags)).
- Regenerating committed outputs, when a change is meant to alter them: `UPDATE_GOLDEN=1` (golden
  projects), `UPDATE_PACK=1` (the conformance pack), `UPDATE_GENERATED=1` (the API's generated
  methods) and `UPDATE_GUIDE=1` (the guide's screenshots). Say in the pull request which you ran
  and why the outputs changed.

## What a change needs

- Every change to a document goes through a command ([`docs/core.md`](docs/core.md)); the editor,
  the API, the MCP server and the CLI share them. A new command comes with its schema, errors,
  examples and tests, including the command laws.
- Tests for what changed, and `npm run check` passing.
- Documentation in `docs/` for anything a person or an agent uses.
- No machine-learning features without discussing them in an issue first.
- Images, models and sounds that are generated by this project's code, as
  [`ASSETS.md`](ASSETS.md) describes; no third-party art or models.
- Descriptive wording about other products: Mochi Maker makes models for Live2D Cubism-compatible
  apps; it is not presented as a replacement for, or part of, anyone else's product.

## Clean-room statement

Mochi Maker is written without Live2D's software development kit or any other implementation of
its file formats (see [`CLEANROOM.md`](CLEANROOM.md)). Every pull request must include this
statement, and by signing off you confirm it:

> I have not viewed, decompiled or copied Live2D's SDK, Cubism Core, Framework, sample code or manuals, or third-party `.moc3` implementations, for this contribution.

## Developer Certificate of Origin

Contributions are accepted under the [Developer Certificate of Origin](https://developercertificate.org/)
(DCO) 1.1: by signing off a commit, you certify that you wrote it or otherwise have the right to
submit it under the project's license (MIT). Add the sign-off to every commit:

```sh
git commit -s
```

which adds a line with your name and email:

```
Signed-off-by: Your Name <you@example.com>
```

Commits without a sign-off cannot be merged.

## Reporting bugs and security issues

Bugs go in GitHub issues, with the steps to reproduce them and, if you can, a project that shows
them. Security issues do not: report them privately as [`SECURITY.md`](SECURITY.md) describes.
